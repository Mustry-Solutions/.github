# Contributing to Mustry Solutions projects

Thanks for your interest in improving our tools. These guidelines apply to all public
repositories in the Mustry-Solutions organization unless a repository has its own
CONTRIBUTING file.

## Before you start

- **Found a bug?** Open an issue with reproduction steps and version details. For
  Ignition-related projects, always mention your Ignition version.
- **Have a feature idea?** Open an issue first so we can discuss the approach before
  you invest time in code.
- **Security issue?** Do not open an issue. See our [security policy](SECURITY.md).

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep changes focused: one fix or feature per pull request.
3. Match the style and conventions of the surrounding code.
4. Test your changes and describe how you tested them in the pull request.
5. Reference the related issue in the description if there is one.

We review pull requests as time allows. We are a consultancy first, so responses can
take a little while during busy project periods. Pinging after two weeks is fine.

## Questions

Not sure about something? Open an issue or reach out at
[info@mustrysolutions.com](mailto:info@mustrysolutions.com).
